- **Два языка интерфейса**: английский по умолчанию, русский по выбору. Новая настройка `language`
  (`en` / `ru`) проведена через `SettingsKey`, `registerDefaults()`, `SettingsConfig` и окно настроек:
  вкладка «Drag / Перетаскивание» → «Language / Язык». Сброс настроек язык не меняет.
  Все строки интерфейса переведены и пишутся через `tr(en, ru)` из нового
  `Settings/Localization.swift`; `SettingsView` и `MenuView` пересоздаются при смене языка (`.id`).
  Комментарии в `config.txt` и `default-config.txt` тоже двуязычные (`comment` + `commentRu`),
  `default-config.txt` в репозитории теперь на английском.
- Заголовок окна настроек задаётся через `.navigationTitle`, чтобы меняться вместе с языком.
- **Установка одной командой**: `install.sh` скачивает готовую universal-сборку из GitHub Releases
  в `/Applications/GOBL(in) Drag`, сохраняя `config.txt`. `package.sh` собирает архив
  `dist/goblin-drag-macos.zip` для релиза; `dist/` добавлена в `.gitignore`.
- `BuildInfo.swift` больше не хранится в git: `build.sh` создаёт его при каждой сборке, и раньше любая сборка
  оставляла изменённый файл в рабочей копии.
- Из документации и `build.sh` убраны ссылки на папку `TwoFingerDragWin/`: прототип для Windows —
  отдельный проект, в этом репозитории его нет.

## 2026-08-17 16:21 MSK · Terminal · Claude Code · Claude Opus 5

- **Три режима сборки в `build.sh`** (режим — первым аргументом): `./build.sh` — arm64
  Apple Silicon (дефолт), `./build.sh intel` — x86_64, `./build.sh universal` — оба среза
  в одном бинарнике через `lipo`. `./build.sh windows` намеренно ничего не собирает и
  печатает напоминание, `--help` выводит шпаргалку, неизвестный режим — выход с кодом 1.
  Раньше архитектура была жёстко зашита как `x86_64-apple-macosx13.0`.
- `build.sh` теперь кладёт в `BuildInfo.swift` ещё и `arch`; меню трея показывает строку
  «Архитектура», а сам скрипт в конце печатает `lipo -archs` собранного бинарника.
- **Убран хардкод пути к конфигу.** `SettingsConfig` больше не ссылается на несуществующий
  `/Users/user/asd/asd4/config.txt`: добавлен `SettingsConfig.projectDirectory`, который
  вычисляет папку от `Bundle.main.bundleURL` (для запуска без бандла — папка исполняемого
  файла). `config.txt` и `default-config.txt` лежат рядом с `TwoFingerDrag.app`, поэтому
  проект можно переносить и переименовывать. До правки приложение писало настройки
  по несуществующему пути, и `config.txt` в папке проекта не обновлялся.
- **Новый режим перетаскивания `fingers = 3` — «только при зажатой правой кнопке мыши».**
  Окно едет за курсором (1:1), пока зажаты модификатор перетаскивания И правая кнопка.
  Свайпы в этом режиме выключены (`scrollWheel`-ветки завязаны на `fingers == 1|2`).
- Маска event tap расширена: `rightMouseDown | rightMouseDragged | rightMouseUp`.
  Правый клик поглощается ТОЛЬКО при зажатом модификаторе — без модификатора контекстное
  меню работает как раньше. Введён флаг `rightButtonDragActive`: поглощённому
  `rightMouseDown` обязан соответствовать поглощённый `rightMouseUp`, иначе приложение
  под курсором получит непарное событие. Если модификатор отпущен посреди жеста —
  окно больше не двигается, но события продолжают поглощаться до отпускания кнопки.
  Зажатый Shift (`shiftCancelsDrag`) отменяет движение и в этом режиме тоже.
- UI: в `DragSettingsTab` третий пункт переключателя «Жест» с пояснением; в
  `SwipeSettingsTab` для нового режима отдельный текст, почему свайпы недоступны.
  Ключ `fingers` проведён по §8 (комментарий в `SettingsConfig` обновлён под три значения).
- Документация: `AGENTS.md` — переписаны §2 (варианты сборки), §3 (окружение больше не
  привязано к Intel), §4 (структура без абсолютных путей), §8 и §9 (правила правой кнопки);
  добавлен §3.1 «Windows пока не трогаем». Аналогичные пометки — в `CLAUDE.md` и в шапке
  `TwoFingerDragWin/AGENTS_WINDOWS.md`. Windows-прототип заморожен и не изменялся.
- Создан сертификат `TwoFingerDrag Codesign` (`./create-cert.sh`) — сборка снова
  подписывается стабильной идентичностью (`Authority=TwoFingerDrag Codesign`,
  `flags=0x0(none)`), а не ad-hoc, поэтому разрешение Universal Access перестаёт
  слетать после каждой пересборки.

## 2026-06-13 15:57 MSK · Terminal · Codex CLI · GPT-5

- Добавлен отдельный Windows-прототип `TwoFingerDragWin` в подпапке проекта: консольное
  C#/.NET-приложение с Win32 message loop и глобальными keyboard/mouse low-level hooks.
- Добавлен нативный tray-значок через Win32 `Shell_NotifyIcon`: левый клик ставит
  обработку жестов на паузу/включает обратно, правый клик завершает приложение.
- v0 использует Alt как модификатор: Alt + движение мыши двигает root-окно под
  курсором через Win32 `WindowFromPoint`/`GetAncestor`/`SetWindowPos`, а Alt +
  горизонтальный wheel сворачивает окно через `ShowWindow(SW_MINIMIZE)`.
- Добавлен диагностический лог входящих mouse/keyboard events, координат, wheel-delta,
  modifiers, hwnd и заголовка окна, чтобы на Windows 10/11 проверить, как Boot Camp
  отдаёт трекпадные жесты.
- По результатам Windows-лога расширена диагностика и управление: активным
  модификатором считаются Alt, Ctrl или Win; в лог пишется имя клавиши и `active`,
  а максимизированное окно перед перетаскиванием восстанавливается.
- Для Windows-прототипа добавлена macOS-похожая вертикальная логика двухпальцевого
  scroll: модификатор + scroll вверх разворачивает окно, scroll вниз сворачивает.
  Обработанные wheel-события поглощаются low-level hook'ом, чтобы Ctrl+scroll не
  уходил дальше в системный/приложенческий масштаб.
- Назначение модификатора Windows-прототипа возвращено к одному Alt как аналогу
  macOS Option; Ctrl и Win больше не запускают drag/swipe-действия.
- Клик по tray-иконке Windows-прототипа теперь открывает нативное меню настроек:
  Enabled, текущий модификатор Alt, краткие действия жестов и Exit. Пункт Enabled
  ставит обработку жестов на паузу или включает обратно.
- Модификатор Windows-прототипа возвращён на Ctrl; tray-меню переведено на более
  совместимую обработку кликов без `NOTIFYICON_VERSION_4` и через обычное скрытое
  Win32-окно.
- Maximize для Windows-прототипа переведён с `ShowWindow(SW_MAXIMIZE)` на явную
  установку рамки окна по рабочей области экрана через `SystemParametersInfo`.
  Tray-меню расширено статусом, модификатором, разделами Drag/Two-finger scroll и
  ссылкой на папку логов.
- Добавлен отдельный `TwoFingerDragWin/AGENTS_WINDOWS.md` с актуальной инструкцией
  для будущего агента: архитектура, сборка на macOS в Windows `.exe`, Win32 hooks,
  tray-меню, window control, результаты ручных тестов, ограничения и дальнейшие шаги.
- Добавлена инструкция и reusable build-скрипт в `/Users/user/asd/algoritm2` с
  обратной ссылкой из `TwoFingerDragWin/README.md`; publish собирает single-file
  self-contained Windows `.exe`.
