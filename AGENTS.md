Это **единственный** канонический документ проекта (README и onboarding-инструкция
объединены). Раздел 2 — для пользователя. Разделы 3+ — для агента, который дорабатывает

## 1. Что это за программа

Утилита для macOS: **перетаскивание и управление окнами жестами трекпада**, живёт
иконкой в строке меню (трее), без иконки в Dock (приложение-агент, `LSUIElement`).

**Имя.** Для пользователя приложение называется **GOBL(in) Drag** — так оно названо на сайте
goblin.red; это имя носят `.app`, меню в трее и окно настроек (`APP_NAME` в `build.sh`).
Внутреннее имя **TwoFingerDrag** осталось у исполняемого файла (`EXEC_NAME`), папки исходников,
bundle id `com.local.twofingerdrag` и сертификата подписи. 🔴 Bundle id и сертификат не
переименовывать — иначе слетит выданное разрешение Accessibility (см. §7).

Текущий функционал (ВСЁ реализовано и работает):
- **Перетаскивание окна под курсором** при зажатом модификаторе (⌘/⌥/⌃):
  - режим **1 палец** — окно едет ровно за курсором (1:1, плавно);
  - режим **2 пальца** — окно двигается жестом скролла (с настраиваемым усилением);
  - режим **правая кнопка мыши** — окно едет за курсором, только пока зажаты
    модификатор И правая кнопка; правый клик под модификатором поглощается
    (контекстное меню не появляется), свайпы в этом режиме выключены.
- **Свайпы двумя пальцами** (режим «1 палец», зажат модификатор перетаскивания):
  - по умолчанию **влево** — свернуть окно, **вправо** — свернуть (по окну под курсором через AX, либо ⌘M/⌘W активному);
  - действие левого и правого свайпа настраивается отдельно: закрыть или свернуть, можно выбрать одно действие для обоих;
  - **вверх** — развернуть окно (maximize по `visibleFrame`), **вниз** — вернуть прежний размер.
- **Расширить окно двойным кликом**: модификатор + двойной клик — тоггл «развернуть ↔ вернуть»
  (по умолчанию выключено, включается в настройках).
- **Активация окна при управлении**: опционально окно под курсором становится активным,
  когда приложение начинает им двигать или выполнять над ним действие (по умолчанию включено).
- **Активация по модификатору**: простое нажатие выбранного модификатора (⌘/⌥/⌃)
  активирует окно под курсором даже без движения мыши; клавиша задаётся отдельно
  от модификатора перетаскивания (по умолчанию включено).
- **Переключение приложений**: выбранный модификатор + Tab (по умолчанию ⌥+Tab)
  показывает собственную центральную панель TwoFingerDrag с квадратной сеткой иконок
  видимых приложений текущего рабочего стола; повторный Tab выбирает следующее,
  отпускание модификатора активирует выбранное приложение. Системная панель ⌘Tab не вызывается.
- **Изменение размера** (отдельный модификатор, по умолч. Control + свайп двумя пальцами):
  симметрично от центра, относительный знак (первое движение увеличивает, разворот — уменьшает).
- **Окно настроек** (вкладки) + компактное меню в трее с датой сборки, потоком tap'а и PID.
- **Защита от второго экземпляра**: при повторном запуске новый процесс завершается,
  если уже найден другой `TwoFingerDrag` с тем же bundle id.

> Статус: специальной «недоделанной» задачи сейчас нет — всё перечисленное работает.
> Дальнейшие доработки — по запросу пользователя, строго по правилам §6.
> **Pinch (magnify) сознательно НЕ делаем** — публичными API глобально невозможно (см. §10).

## 2. Использование (для пользователя)

### Сборка и запуск
```bash
./create-cert.sh     # один раз: создаёт сертификат для подписи (см. §7)
./build.sh           # собирает «GOBL(in) Drag.app»: arm64 + x86_64 (по умолчанию)
open "GOBL(in) Drag.app"
```

### Варианты сборки (три режима)
Режим задаётся первым аргументом `build.sh`:

| Команда | Что собирает | Когда нужен |
|---|---|---|
| `./build.sh` | **arm64 + x86_64** в одном бинарнике (склейка через `lipo`). **Дефолт** | одна сборка, работает на любом Mac |
| `./build.sh arm` | **arm64** — только Apple Silicon (M1/M2/M3) | быстрая сборка для своего Mac |
| `./build.sh intel` | **x86_64** — только Intel Mac | сборка для старого Mac на Intel |
| `./build.sh windows` | ничего не делает, печатает предупреждение | 🚫 **Windows пока не трогаем** (см. §3.1) |

`./build.sh --help` печатает эту же шпаргалку. Неизвестный режим — ошибка и выход с кодом 1.

Проверить, что получилось: `lipo -archs "GOBL(in) Drag.app/Contents/MacOS/TwoFingerDrag"`
(скрипт печатает это сам в конце). Текущая архитектура сборки также видна в меню трея
строкой «Архитектура» — её кладёт в `BuildInfo.arch` сам `build.sh`.

### Выдать разрешение (один раз)
Приложению нужен **Универсальный доступ**: *Системные настройки → Конфиденциальность
и безопасность → Универсальный доступ* → включить `GOBL(in) Drag`. Без него перехват
жестов и перемещение окон не работают (это защита системы, обойти нельзя).
Благодаря стабильной подписи разрешение **сохраняется между пересборками**.

### Как пользоваться (по умолчанию модификатор ⌥)
- **Перетащить окно:** зажми ⌥ и веди курсор (режим «1 палец») — окно под курсором едет
  за курсором. В режиме «2 пальца» — веди двумя пальцами по трекпаду.
  В режиме «только при зажатой правой кнопке мыши» — зажми ⌥ **и** правую кнопку, затем веди.
  Пока держишь модификатор, правый клик не открывает контекстное меню; отпустишь модификатор —
  правый клик снова работает как обычно.
- **Свайпы двумя пальцами (режим «1 палец», зажат ⌥):**
  - по умолчанию влево → свернуть, вправо → свернуть; действие каждого направления можно поменять в настройках;
  - вверх → развернуть окно, вниз → вернуть прежний размер.
- **Двойной клик** (⌥ + двойной клик) → развернуть/вернуть окно, если включён в настройках.
- **Изменение размера:** зажми **Control** + свайп двумя пальцами (нужно включить в настройках).
- Настройки — иконка в трее → «Настройки…». Меняются на лету, перезапуск не нужен.
- Текстовый конфиг: `config.txt` в рабочей директории проекта. Он создаётся автоматически, читается при
  запуске приложения и содержит комментарии по всем настройкам.

### Важно
- Окно настроек **самого приложения** нельзя двигать/трогать этим жестом — это
  сознательное ограничение (см. §6.1). Двигай его обычным способом, за заголовок.
- Если жест ⌥ конфликтует с шорткатами приложений — выбери в настройках ⌘ или ⌃.

## 3. Окружение сборки

- Собираем **напрямую `swiftc`**: полного Xcode нет, установлены только Command Line Tools,
  поэтому `xcodebuild` и SwiftPM (`swift build`) **не работают** (нет PlatformPath).
  `.app`-бандл и `Info.plist` лепим вручную в `build.sh`.
- Доступны: `swiftc`, `clang`, `codesign`, `plutil`, `lipo`, `openssl` (3.x из Homebrew).
- **Целевая архитектура не привязана к машине сборки.** `build.sh` умеет собирать под arm64,
  под x86_64 и оба сразу (см. таблицу режимов в §2). Минимальная macOS для всех
  режимов — **13.0** (`MIN_MACOS` в `build.sh`).
- 🟠 Не хардкодь архитектуру в скрипте и не подставляй `uname -m`: режим выбирает
  пользователь аргументом, дефолт — universal (оба среза).

### 3.1. 🚫 Windows пока не трогаем

Прототип для Windows на C#/.NET (Win32 hooks, tray) — **отдельный проект, в этом репозитории
его нет**. Работы по нему ведутся **только по отдельному явному запросу пользователя**.

- `./build.sh windows` намеренно ничего не собирает, а печатает напоминание.
- Любые правки по проекту (пути, конфиги, скрипты) касаются **только macOS-части**.

├── AGENTS.md                  # ЭТОТ файл — единственная документация

то есть в папке проекта; путь вычисляется от `Bundle.main` (`SettingsConfig.projectDirectory`).

### Модульная ownership-структура
Перед правкой читай общий документ + релевантный блок:
- `UI/` — только визуальная часть SwiftUI. Не импортировать `ApplicationServices`, не
  трогать `CGEvent`, `AXUIElement`, event tap или `WindowAccess`.
- `Settings/` — `SettingsKey`, enum-ы настроек, `SettingsConfig`. Новая настройка должна
  пройти через defaults, config, UI-сброс и чтение в движке.
- `Windowing/WindowAccess.swift` — единственные ворота к `AXUIElement`, `CGWindowList`,
  поиску окна под курсором, геометрии, activation/minimize/close helpers. 🔴 Прямые
  AX-вызовы вне этого файла не добавлять.
- `Gestures/` — чистая математика и будущие движки жестов. Они не должны напрямую
  обращаться к AX; взаимодействие с окнами только через `WindowAccess`/контракты
  `DragController`.
- `AppSwitcher/` — панель переключения приложений и её hit-test/визуальная часть.

### Settings/SettingsConfig.swift / config.txt
Все настройки приложения должны быть представлены в текстовом конфиге `config.txt`.

🔴 **Путь к конфигу не хардкодить.** `SettingsConfig.projectDirectory` вычисляет папку от

Файл создаётся автоматически при первом запуске, содержит
простые строки `key = value` и комментарии к каждой настройке. При запуске приложение

### App.swift
- `AppDelegate.applicationDidFinishLaunching`: `NSApp.setActivationPolicy(.accessory)` + `controller.start()`.
- Перед запуском tap'а `AppDelegate` проверяет single-instance guard по bundle id
  `com.local.twofingerdrag`; второй процесс должен завершиться и не ставить event tap.
- `TwoFingerDragApp`: сцена `MenuBarExtra` (стиль `.window`) с `MenuView` и сцена `Window(id:"settings")` с `SettingsView`.
- `UI/AppShell/MenuView.swift` — компактное меню в трее (логотип `BrandLogo`, вкл/выкл, «Настройки…», «Выйти»). При клике
  «Настройки…» окно меню трея должно закрываться.
- `UI/Settings/SettingsView.swift` — окно настроек (`Form`, `.formStyle(.grouped)`), кнопка сброса.
  Вкладки лежат отдельными файлами в `UI/Settings`, общие визуальные элементы — в
  `UI/DesignSystem/SettingsUI.swift`.
  - 🟠 **Почему настройки в отдельной `View`, а не в структуре `App`:** в `MenuBarExtra(.window)`
    `@AppStorage` в самой `App` «залипал» (тумблеры не переключались). В дочерней `View` всё ок.

### DragController.swift
Класс `DragController` остаётся владельцем event tap и диспетчером текущих gesture-flow.
Типы настроек (`DragModifier`, `WindowSwipeAction`, `SettingsKey`) живут в
`Settings/SettingsTypes.swift`. Ключевые методы:
- `start()` — регистрирует дефолты, просит Accessibility, запускает event tap **на отдельном потоке** (запоминает `tapThreadID`).
- `setupEventTap()` — `CGEventTap` (mouseMoved | flagsChanged | keyDown | scrollWheel | leftMouseDown).
- `handle(type:event:)` — диспетчер: re-enable tap → `enabled` → **модификатор ресайза (приоритет)** → модификатор перетаскивания → по типу события.
- `handleOneFinger(location:)` — окно за курсором (1:1).
- `handleTwoFinger(event:)` — окно жестом скролла (с `sensitivity`).
- `handleSwipe(event:defaults:)` — свайп: горизонталь (свернуть/закрыть), вертикаль (развернуть/вернуть). Поглощает весь жест.
- `handleResize(event:defaults:)` / `beginResize` / `endResize` — изменение размера (симметрично, относительный знак).
- `zoomWindow` (тоггл двойным кликом) / `maximizeWindow` / `restoreWindow` — «расширить окно»; память в `zoomMemory`.
- `beginDrag(at:)` / `endDrag()` — старт/стоп перетаскивания.
- `scheduleApply`/`applyLoop` (позиция) и `scheduleApplyFrame`/`applyFrameLoop` (position+size) — фон + «склейка».
- `WindowAccess.windowUnderPoint(_:)` → `enclosingWindow(of:)` — поиск окна под точкой; 🔴 сначала `isPointOverOwnWindow(_:)` (CGWindowList), затем AX hit-test, затем fallback через верхнее окно из `CGWindowList` → AX-окно приложения по `AXWindowNumber`/рамке.
- `WindowAccess.windowPosition`/`setWindowPosition`, `windowSize`/`setWindowSize`, `windowFrame` — AX-геометрия.
- `WindowAccess.visibleFrameTopLeft(containing:)` — visibleFrame экрана под точкой (конвертация NSScreen ↔ top-left).
- `postShortcut(_:)`, `minimizeWindow(at:)`, `closeWindow(at:)` — действия (⌘-клавиша / свернуть / закрыть).
- `Gestures/ResizeCalculator.swift` — чистая математика resize frame/edge shares без AX.

## 6. 🔴 КРИТИЧЕСКИЕ ПРАВИЛА (нарушение = зависание/баги)

### 6.1. Никогда не выполняй AX-операции над окнами СВОЕГО процесса
AX-вызовы над окнами **собственного** приложения выполняются **внутрипроцессно** и
требуют главного потока + замок иерархии вью AppKit. Из фонового потока (а tap у нас
на фоновом) это даёт **тройную взаимоблокировку**: tap-поток ждёт в
`AXUIElementCopyElementAtPosition`, apply-поток ждёт в `setFrame` нашего окна, главный
ждёт замок. Весь app виснет (beachball). **Воспроизведение:** открыть «Настройки», навести
курсор (не активируя) и применить жест к окну настроек.

**Защита:** `WindowAccess.windowUnderPoint(_:)` сначала зовёт `isPointOverOwnWindow(_:)`, который
определяет владельца окна под точкой через `CGWindowListCopyWindowInfo` (запрос к
оконному серверу, БЕЗ внутрипроцессных замков) и возвращает `nil` для своих окон.
**Любая фича, трогающая «окно под курсором», обязана идти через `WindowAccess.windowUnderPoint`
или сама проверять PID.** Не зови AX по точке, не отфильтровав свой процесс.

### 6.1.1. AX hit-test иногда не видит видимое окно
После сворачивания предыдущего окна macOS может оставить активным старое приложение,
а `AXUIElementCopyElementAtPosition` иногда возвращает не окно или вообще не даёт
элемент для видимого окна под курсором (поймано на LibreOffice после сворачивания
Terminal/Finder). При этом `CGWindowListCopyWindowInfo([.optionOnScreenOnly])`
корректно показывает верхнее layer-0 окно под точкой.

**Решение в `WindowAccess.windowUnderPoint(_:)`:**
1. Сначала `isPointOverOwnWindow(_:)` через `CGWindowList` — защита от deadlock на своих окнах.
2. Затем обычный AX hit-test: `AXUIElementCopyElementAtPosition` → `enclosingWindow(of:)`.
3. Если AX hit-test не дал окно, fallback: взять верхнее обычное окно под точкой из
   `CGWindowList`, создать `AXUIElementCreateApplication(pid)`, получить `kAXWindowsAttribute`
   и найти AX-окно по `"AXWindowNumber"`. Если номер недоступен или не совпал — выбрать
   AX-окно, чья `windowFrame` содержит точку и ближе всего к bounds из `CGWindowList`.

🔴 Не удаляй этот fallback как «лишний»: без него свайпы/активация могут перестать
работать на видимом окне, если фокус macOS остался на уже свёрнутом приложении.

### 6.2. Event tap живёт на отдельном потоке, НЕ на главном
`start()` поднимает `Thread` → `setupEventTap()` + `CFRunLoopRun()`. 🔴 Не переноси
источник tap'а в главный run loop — синхронные AX-вызовы заблокируют UI.

### 6.3. Применение изменений окна — только фон + склейка
`AXUIElementSetAttributeValue` медленный (IPC). Звать его прямо в обработчике событий
нельзя — tap отваливается по таймауту, рывки. `applyLoop` на `applyQueue` применяет
только самую свежую цель, промежуточные отбрасывает. 🔴 Новые операции с геометрией
окна (resize и т.п.) проводи через тот же механизм (или его аналог для frame).

### 6.4. Bash + кириллица/многоточие в `build.sh`
🟠 В `echo "...$VAR…"` (переменная вплотную к многобайтовому символу `…`,`»`) при
не-UTF-8 локали bash ломается (`unbound variable`). **Всегда `${VAR}`** + пробел перед символом.

### 6.5. codesign может разово подвиснуть на диалоге keychain
🟠 При первой подписи новым ключом всплывает диалог «разрешить codesign доступ к ключу».
Если сборка зависла на шаге подписи — это он. Нажми **«Всегда разрешать»**.

## 7. Подпись и разрешения (почему так)

- Нужен **Accessibility**: перехват глобальных событий (`CGEventTap`) и перемещение
  чужих окон (`AXUIElement`).
- macOS привязывает TCC-разрешение к **удостоверению кода** (cdhash). Ad-hoc подпись
  меняет cdhash при каждой сборке → разрешение слетает.
- Решение: самоподписанный сертификат **«TwoFingerDrag Codesign»** в login-keychain
  (`./create-cert.sh`, через `openssl` с `-legacy` PKCS12). `build.sh` подписывает им →
  удостоверение стабильно, разрешение выдаётся один раз.
- Сертификат недоверенный (`CSSMERR_TP_NOT_TRUSTED`) — это нормально; для подписи и для
  совпадения TCC доверие не нужно. bundle id: `com.local.twofingerdrag`.

## 9. Модель перехвата событий

- Tap: `.cgSessionEventTap`, маска `mouseMoved | flagsChanged | keyDown | scrollWheel |
  leftMouseDown | rightMouseDown | rightMouseDragged | rightMouseUp`.
- Правые кнопочные события нужны только режиму `fingers == 3`. Правила режима:
  - `rightMouseDown` **при зажатом модификаторе** → `beginDrag`, событие **поглощаем**
    (иначе поверх перетаскивания вылезет контекстное меню); поднимаем флаг
    `rightButtonDragActive`;
  - `rightMouseDragged` при поднятом флаге → `handleOneFinger` (1:1), поглощаем;
    если модификатор уже отпущен — окно не двигаем, но событие продолжаем поглощать;
  - `rightMouseUp` при поднятом флаге → `endDrag`, поглощаем и снимаем флаг.
  - 🔴 Поглощённому `rightMouseDown` **обязан** соответствовать поглощённый `rightMouseUp` —
    иначе приложение под курсором получит непарное событие. Именно для этого и нужен флаг,
    а не проверка модификатора в момент отпускания.
  - Без модификатора правые события не трогаем вовсе — обычное контекстное меню работает.
- `keyDown` ловит выбранный модификатор + Tab для собственного переключателя приложений:
  событие поглощается, системный ⌘Tab не отправляется; `flagsChanged` при отпускании
  модификатора закрывает панель и активирует выбранное приложение.
- `flagsChanged` ловит **отпускание модификатора** → `endDrag()`/`endResize()`.
- `flagsChanged` также ловит первое нажатие выбранного модификатора активации и при включённом
  `activateOnModifierPress` активирует окно под курсором через `windowUnderPoint`.
- `mouseMoved` при включённом `activateOnModifierHover` и зажатом `activateModifier`
  активирует окно под курсором через `WindowAccess.activateWindowUnderPoint`; вызов
  throttled, чтобы не слать AX-активацию на каждый пиксель.
- `mouseMoved` при зажатом Option и включённом `optionMouseDrag` дублирует
  перетаскивание окна курсором в режиме «1 палец» через тот же `handleOneFinger`.
- `scrollWheel` при зажатом Option может дублировать swipe-действия основного
  модификатора: `optionSwipeHorizontal` включает влево/вправо, `optionSwipeVertical`
  включает вверх/вниз. Если resize-модификатор тоже Option, resize остаётся выше по
  приоритету. Если основной `modifier` уже Option, обычный swipe-flow уже покрывает
  этот сценарий.
- Диспетчер `handle()`: re-enable → `enabled` → **сначала** модификатор ресайза (если включён и зажат +
  scrollWheel → `handleResize`) → затем модификатор перетаскивания; если не зажат → `endDrag()` + пропуск; иначе по типу:
  - `fingers==3` && правые кнопочные события → перетаскивание правой кнопкой (**поглощаем**,
    см. правила выше); свайпы и `mouseMoved`-перетаскивание в этом режиме не работают;
  - `mouseMoved` && `fingers==1` → `handleOneFinger` (**НЕ поглощаем** — курсор должен двигаться);
  - `scrollWheel` && `fingers==2` → `handleTwoFinger` (**поглощаем**);
  - `scrollWheel` && `fingers==1` → `handleSwipe` (**поглощаем весь жест** — и горизонталь, и вертикаль);
  - `leftMouseDown` && `zoom` && `clickState==2` → `zoomWindow` (поглощаем двойной клик; по умолчанию выключено).
- Возврат `nil` = поглотить; `Unmanaged.passUnretained(event)` = пропустить.
- 🟠 magnify (pinch) в маске НЕТ — публичными API не ловится (см. §10), не добавляй обратно.
- Координаты: `event.location`, AX `kAXPositionAttribute`, `CGWindowList` bounds — **все
  сверху-слева**, совпадают. ВНИМАНИЕ: `NSScreen` — снизу-слева (нужна конвертация при maximize/resize).
- Поиск окна под курсором обязан учитывать fallback из §6.1.1: `CGWindowList` может
  видеть правильное видимое окно, даже когда AX hit-test по точке не возвращает окно.
- Дельты трекпада: `scrollWheelEventPointDeltaAxis1` (вертикаль), `Axis2` (горизонталь),
  пиксельные. Инерцию (`scrollWheelEventMomentumPhase != 0`) игнорируем.

### 10.1. «Расширить окно» — ⌘ + двойной клик

**Хотелка:** удерживая модификатор перетаскивания (⌘), сделать **двойной клик** по окну
под курсором → окно «расширяется» (аналог зелёной/третьей кнопки).

**Развилка поведения (выбрать при реализации):**
1. **Полноэкранный режим** (дефолт зелёной кнопки) — обычно НЕ то, что хотят под «расширить».
2. **Развернуть по `visibleFrame` экрана (maximize)** — РЕКОМЕНДУЕТСЯ; желателен тумблер
   «вернуть прежний размер при повторном двойном клике».
3. **Нажать зелёную кнопку как есть:** `kAXZoomButtonAttribute` → `AXUIElementPerformAction(_, kAXPressAction)`.

**Эскиз встройки:**
1. Добавить в маску tap'а `.leftMouseDown`.
2. В `handle()` (модификатор уже проверен зажатым) — ветка:
   ```swift
   case .leftMouseDown where defaults.bool(forKey: SettingsKey.zoom):
       if event.getIntegerValueField(.mouseEventClickState) == 2 { // двойной клик
           let loc = event.location
           applyQueue.async { [weak self] in self?.zoomWindow(at: loc) }
           return nil // поглотить (обсуждаемо)
       }
       return Unmanaged.passUnretained(event)
   ```
3. `zoomWindow(at:)`: окно брать через `windowUnderPoint` (🔴 пропускает свои окна);
   maximize → найти экран под точкой (`NSScreen`, конвертация координат!) и выставить
   `kAXPositionAttribute` + `kAXSizeAttribute` в `visibleFrame`.
4. Настройка `zoom` (Bool) + при желании `zoomMode` ("maximize"|"fullscreen"|"zoombutton").

**Камни:** двойной клик по своему окну (отсекает `windowUnderPoint`); конфликт ⌘+двойной
клик в приложениях (поглощение подавит); многомониторные координаты; AX — на `applyQueue`.

### 10.2. «Изменение размера окна» — Control + свайп двумя пальцами

**Спецификация (подтверждена пользователем, неоднозначностей нет):**

Удерживая **отдельный** модификатор (по умолчанию **Control**, настраивается отдельно
от модификатора перетаскивания) и делая свайп двумя пальцами, пользователь меняет размер
окна под курсором — **симметрично от центра, непрерывно и обратимо**:

1. **Симметрия от центра.** Центр окна остаётся на месте; противоположные края
   расходятся/сходятся РАВНОМЕРНО:
   - **горизонтальный** свайп → меняется **ширина** (левый и правый край симметрично);
   - **вертикальный** свайп → меняется **высота** (верхний и нижний край симметрично).
2. **Относительный знак (ключевой момент).** **Первое** движение жеста — в ЛЮБУЮ сторону —
   **увеличивает** окно. Если, не завершая жест, повести пальцы в **обратную** сторону —
   окно начинает **уменьшаться**. То есть «больше/меньше» определяется не абсолютным
   направлением (вверх/вниз/влево/вправо), а тем, **продолжаешь** ты движение (рост) или
   **разворачиваешь** (уменьшение).
3. Следствие: **знак дельт трекпада НЕ важен** — направление «расти» задаётся знаком
   первого движения (`initDir`). Подбирать знаки осей, в отличие от §9, НЕ нужно.

**🔴 Развязка с другими жестами:** режим использует **свой** модификатор, отличный от
модификатора перетаскивания. В `handle()` проверять модификатор ресайза **раньше** логики
перетаскивания/свайпов. В настройках 🟠 запретить выбирать одинаковый модификатор для
перетаскивания и ресайза.

**Алгоритм (точный):**
- `beginResize(at:)`: `windowUnderPoint(loc)` (🔴 свои окна); прочитать стартовые
  `P0 = kAXPositionAttribute`, `S0 = kAXSizeAttribute`; центр `C = (P0.x+S0.w/2, P0.y+S0.h/2)`;
  обнулить `accX, accY`; `axisLocked = nil`; `initDir = 0`.
- На каждом scroll-событии: `accX += axis2`, `accY += axis1`.
  - Пока ось не зафиксирована: как только `max(|accX|,|accY|)` превысит малый порог —
    `axisLocked = (|accX| >= |accY|) ? .horizontal : .vertical`, и
    `initDir = sign(значения накопителя по выбранной оси)`.
  - После фиксации: `progress = accumulated[axisLocked] * initDir` (вперёд → растёт,
    разворот → убывает, может уйти в минус);
    `delta = gain * progress`.
  - Если ось горизонтальная: `newW = clamp(S0.w + delta, minW, …)`, `newH = S0.h`.
    Если вертикальная: `newH = clamp(S0.h + delta, minH, …)`, `newW = S0.w`.
  - **Центр фиксирован:** `newX = C.x - newW/2`, `newY = C.y - newH/2`.
  - Применить новый frame; вернуть `nil` (поглотить скролл).
- momentum (`scrollWheelEventMomentumPhase != 0`) → `nil` (не двигаем). `phase==1`/пауза → новый `beginResize`.
- При отпускании модификатора (`flagsChanged`) → `endResize()`.

**Применение frame — через фоновую очередь (см. 6.3).** Нужно ставить И position, И size:
ввести `applyFrame` (аналог `applyLoop`, но `setWindowPosition` + `setWindowSize`, где
`setWindowSize` пишет `kAXSizeAttribute` через `AXValueCreate(.cgSize, …)`).
🔴 Не ставить frame синхронно в обработчике. 🔴 Цель — только чужое окно (через `windowUnderPoint`).

**Настройки (провести по §8):**
- `resizeEnabled` (Bool, default true);
- `resizeModifier` (String, default "control"); 🟠 валидировать ≠ `modifier`;
- `resizeGain` (Double, default ~2.0) — множитель скорости изменения размера.
GUI: секция «Изменение размера» в `SettingsView`.

**Решить при реализации (мелочи, не влияющие на суть):**
- Фиксировать ось по началу жеста (рекомендуется — чисто по описанию) или разрешать
  изменение по обеим осям одновременно при диагональном свайпе.
- Минимальный размер (напр. 120×80); ограничивать ли границами экрана.
- Порядок set size / set position при удержании центра (обычно size, затем position).

**Камни:** свои окна (через `windowUnderPoint`); тяжёлые AX — на фоне; конфликт модификатора
с перетаскиванием; clamp размера самим приложением (минимальный размер окна может не дать ужать).
